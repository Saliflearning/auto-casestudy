# Agentic Auto-CaseStudy Constitution

## Principles

### I. Evidence Before Claims

Implemented, partial, simulated, and planned capabilities must be distinguished. Recruiter-facing claims require source evidence and a reproducible verification result.

### II. Privacy Before Visibility

Current files and Git history must pass redacted credential and personal-data review before publication. Fixtures, tests, demos, and screenshots must use synthetic identities and content.

### III. Deterministic Quality Gates

Linting, type checking, tests, dependency audits, and production builds must run non-interactively in CI. Tests may not call paid or production services.

### IV. Secure Boundaries

Uploads, sessions, persistence, reference capture, and publishing inputs are untrusted. Production paths must fail closed when security-critical configuration is absent.

### V. Explicit Repository Provenance

`Agentic_portfolio` and `hci-portfolio-agent` remain separate products and histories. Any migration must name the exact source, destination, reason, and verification. Names, locations, visibility changes, and canonical decisions must be recorded in the shared D: portfolio handoff.

## Portfolio Readiness Gate

Public-showcase approval requires clean current/history privacy scans, zero unresolved high or critical production dependency findings, passing CI, accurate documentation, inspected synthetic visuals, and an explicit HCI/Agentic canonical decision.

## Governance

Substantial changes use a `codex/` branch and Spec Kit artifacts. Commits remain reviewable and are checked for correctness, readability, architecture, security, and performance before merge.
